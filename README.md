## 项目简介

敌人携带着不同的函数进入花园。布置求导塔、选择合适的函数门，把复杂表达式一步步化为常数，守住五条防线。

- **十关递进挑战**：从基础多项式到指数、三角与嵌套函数，逐步解锁单位，收集全部 30 颗星。
- **数学驱动战斗**：六种函数门搭配求导塔，运算顺序就是防守策略。
- **联动防线**：后排炮台可继承前方炮台的最远攻击位置，组成持续输出的火力链。
- **暂停布阵**：来不及时先暂停，放好函数门和炮台再继续；三档触发式炸弹帮助挽回失误。
- **手绘庭院风格**：草坪、木质界面、纸张面板，搭配动态公式和 14 种本地合成音效。
- **账号与存档**：注册登录、最高星数、最快用时、离线成绩补传，以及本机用户管理。

## 快速开始

### 环境要求

- [Git](https://git-scm.com/downloads)
- [Node.js 24 或更新版本](https://nodejs.org/)（包含 npm）
- 现代浏览器，推荐使用电脑横屏游玩

项目使用 Node.js 内置 SQLite，无需另行安装数据库服务。

### 安装与运行

```sh
git clone https://github.com/chenpeng5201107-afk/pvz.git
cd pvz
npm ci
npm test
npm run build
npm start
```

`npm ci` 按锁定版本安装依赖，首次安装需要联网；`npm run build` 完成类型检查并生成前端文件。运行期间请保持终端打开，按 `Ctrl+C` 停止服务。

| 入口     | 默认地址                                                             |
| -------- | -------------------------------------------------------------------- |
| 游戏     | [http://127.0.0.1:3001](http://127.0.0.1:3001)                       |
| 用户管理 | [http://127.0.0.1:3001/database](http://127.0.0.1:3001/database)     |
| 服务状态 | [http://127.0.0.1:3001/api/health](http://127.0.0.1:3001/api/health) |

首次运行请自行注册账号，从第 1 关开始解锁。游戏图片随仓库提供，无需单独下载或生成。

> [!TIP]
> Windows 用户安装好 Node.js 后，也可以双击 [start-local.cmd](start-local.cmd)。没有构建文件时，脚本会准备依赖并构建；已有构建时直接启动。拉取更新后仍需手动重新构建。

## 玩法指南

棋盘为 **5 行 × 9 列**，敌人从右向左移动。求导塔对函数求导，函数门执行一次变换；将函数化为常数即可消灭敌人，漏怪会损失基地生命。

### 基本操作

| 操作               | 方式                                           |
| ------------------ | ---------------------------------------------- |
| 放置单位           | 选择卡牌，再点击棋盘格子                       |
| 选择炮台 / 函数门  | `1`–`7`，仅限已解锁卡牌                        |
| 选择炸弹           | `9` 单格、`0` 范围、`B` 清行                   |
| 开始 / 暂停 / 继续 | 点击按钮或按空格                               |
| 取消选择           | `Esc` 或在棋盘内右键                           |
| 回收单位           | 点击回收或按 `S`，返还原价的 50%；炸弹不可回收 |
| 查看完整公式       | 点击“查看函数”，再点击敌人，自动暂停对局       |
| 打开函数手册       | 点击手册或按 `?`                               |
| 开关音效           | 点击音符按钮，自动记住选择                     |

> [!TIP]
> 来不及安排函数时，先暂停，布置好防线再继续。暂停期间敌人、攻击、能量增长和冷却都会冻结；切换浏览器标签页也会自动暂停。

### 防守规则

- **求导塔**：基础射程为同一行前方两格。射程内有前方求导塔时，继承其最远攻击位置，支持多塔连续传递；前塔被回收或摧毁后重新计算。
- **函数门**：对数、指数、反正弦、正弦、平方、倒数六种一次性变换。敌人经过格子中点时触发，变换先于同一时刻的子弹命中结算。
- **补种**：有敌人的空格仍可放置单位，但已过格子中点的敌人不会被新单位追溯拦截或触发。
- **炸弹**：与炮台、函数门互斥占格。种下后等待敌人经过所在格中点才引爆，不伤己方，且不受函数复杂度影响。

| 炸弹     | 爆炸范围                  | 能量 | 冷却  | 解锁    |
| -------- | ------------------------- | ---- | ----- | ------- |
| 单格炸弹 | 所在格                    | 200  | 30 秒 | 第 2 关 |
| 范围炸弹 | 以所在格为中心的 3×3 区域 | 350  | 45 秒 | 第 6 关 |
| 清行炸弹 | 所在行全部已登场敌人      | 500  | 60 秒 | 第 9 关 |

炸弹仅在战斗开始后可用，暂停时也可种下。放置成功即扣除能量并开始独立冷却，放置失败不扣费；未被踩到时持续等待，仅有敌人在爆炸范围内不会触发。

<details>
<summary><strong>查看数学规则</strong></summary>

- 所有关卡统一约定 **0 < x < 1**，求导与变换遵守此区间上的定义域。
- 数学核心使用表达式树，不使用 `eval`；常数判定依赖符号化简，不依赖数值抽样。
- 支持和、积、常数次幂、链式法则，以及常见三角、反三角、指数、对数函数的求导。
- 逆运算需要满足定义域与主值区间，例如 `arcsin(sin u) = u` 仅在已证明的区间内成立。
- 无法证明合法的变换会保留原式并提示，但已触发的门仍会消耗。
- 运算结果超过 160 个表达式节点时不执行，避免公式无限膨胀。
- 这是面向关卡玩法的数学引擎，不是通用计算机代数系统；需要的求导次数由函数结构决定，不由系数大小决定。

</details>

## 开发指南

### 常用命令

| 命令             | 用途                       |
| ---------------- | -------------------------- |
| `npm ci`         | 安装锁定版本的依赖         |
| `npm run dev`    | 同时启动前端开发服务与后端 |
| `npm run check`  | TypeScript 类型检查        |
| `npm test`       | 运行自动测试               |
| `npm run build`  | 类型检查并构建前端         |
| `npm start`      | 提供构建后的网页与 API     |
| `npm run backup` | 备份 SQLite 存档           |

开发前端默认位于 [http://127.0.0.1:5173](http://127.0.0.1:5173)，后端与用户管理仍使用端口 `3001`。启动开发模式前请停止已有的正式服务，避免端口冲突。`npm start` 不会自动构建或热更新前端。

测试覆盖数学运算、关卡可解性、战斗规则、账号会话、成绩同步、管理接口与静态资源。数据库测试使用独立临时库，不修改正式存档。

### 项目结构

```text
pvz/
├── src/
│   ├── core/             # 数学引擎、关卡配置、战斗模拟
│   ├── game/             # Phaser 场景、美术资源、音效
│   ├── shared/           # 前后端共享类型
│   ├── ui/               # API 请求
│   ├── main.ts           # 页面与存档交互
│   └── style.css         # 响应式样式
├── server/               # HTTP 服务、用户管理、SQLite
├── public/assets/        # 随仓库提供的美术资源
├── tests/                # 自动测试
├── scripts/              # 开发启动与数据库备份
├── start-local.cmd       # Windows 启动脚本
├── package.json
└── package-lock.json
```

数值与关卡配置位于 [content.ts](src/core/content.ts)，战斗逻辑位于 [battle.ts](src/core/battle.ts)，数学逻辑位于 [math.ts](src/core/math.ts)。

### 更新代码

更新前可运行 `npm run backup` 留存快照，然后按 `Ctrl+C` 停止服务。先检查工作区：

```sh
git status
```

如有本地修改，请先提交或另行保存，再执行：

```sh
git switch main
git pull --ff-only origin main
npm ci
npm test
npm run build
npm start
```

`--ff-only` 会在分支出现分歧时停止，不会强制覆盖本地代码。任一步骤报错时应先解决再继续。启动后刷新浏览器；更新代码与构建不会清空存档，请保留 `data/`。

## 用户管理

在运行服务的电脑上打开 [用户管理页面](http://127.0.0.1:3001/database)，可搜索用户、查看注册日期和有效登录数、修改用户名、重置密码、调整关卡成绩、强制退出登录、清空进度或删除账号。

- 管理操作会使目标用户的旧登录失效，需要重新登录。
- 修改成绩会直接覆盖所选关卡的星数和时间，补录高关卡成绩会影响解锁。
- 修改或清空成绩后，旧的离线成绩不能覆盖管理员的调整。
- 清空进度与删除账号需要输入完整用户名确认；操作前建议备份。

> [!WARNING]
> 管理页面无需游戏账号登录，仅在服务监听本机地址时开放。监听 `0.0.0.0` 或局域网地址会关闭管理页面和接口；不要通过反向代理将本机管理入口暴露到公网。

## 存档与备份

账号和通关进度默认保存在项目目录的 `data/game.sqlite`，首次启动自动创建。路径根据项目位置计算，不绑定盘符；也可用 `PVZ_DATA_DIR` 指定独立目录。

`node_modules/`、`dist/`、`data/` 和 `backups/` 不进入版本控制。GitHub 同步的是源码与资源，不包含玩家数据库；新电脑首次启动会创建空存档。

### 备份与恢复

```sh
npm run backup
```

备份输出为 `backups/game-时间戳.sqlite`，支持服务运行时生成一致性快照。

迁移到新电脑或恢复存档：

1. 在原环境执行备份，将生成的文件单独传输到目标电脑。
2. 在目标环境安装依赖并构建，确保游戏服务已停止。
3. 若目标已有 `data` 目录，先将整个目录改名留存，再创建新的 `data` 目录。
4. 将备份放入新目录，命名为 `game.sqlite`。
5. 运行 `npm start`，使用原账号登录并检查进度。

> [!WARNING]
> 不要在服务运行时替换数据库，也不要仅复制正在使用的 `game.sqlite`：最新数据可能仍在 WAL 文件中。备份包含账号信息，应妥善保管，不要上传仓库。使用自定义数据目录时，启动、备份和恢复必须指向同一目录。

### 离线成绩

断网通关时，成绩暂存在当前浏览器中，按账号与关卡分别保留最高星数和最快用时。下次登录或刷新并恢复连接后按关卡顺序补传；清理站点数据或换设备前，请先完成同步。

存档仅保存账号与通关成绩，不保存进行中的战斗。

## 常见问题

**可以直接用 GitHub Pages 部署吗？**

不能运行完整功能。项目需要 Node.js 后端处理登录与存档，上传源码到 GitHub 不会自动启动游戏。公网部署还需要 HTTPS、`COOKIE_SECURE=true`、`NODE_ENV=production`、数据备份及访问安全配置。

**拉取代码后，页面为什么没有变化？**

`npm start` 提供的是 `dist/` 中的构建文件。请重新执行 `npm run build`，重启服务，再刷新浏览器。图片需要向服务端确认更新，带内容哈希的脚本和样式使用长期缓存。

**启动失败或端口被占用怎么办？**

先确认 `node --version` 为 24 或更高、依赖已安装且构建成功；若端口被占用，停止已有服务或通过 `PORT` 换一个端口。PowerShell 若禁止运行 `npm.ps1`，可使用 CMD，或将命令中的 `npm` 改为 `npm.cmd`。

**为什么刚打开页面没有音效？**

浏览器需要一次用户交互才能启用声音。点击页面后，检查音符开关是否开启。

**支持手机、联机或排行榜吗？**

界面适配窄屏，卡牌栏支持横向滚动，手机建议横屏使用。项目以单人电脑端体验为主，不提供联机、排行榜或邮箱找回密码；成绩由客户端上报，不适合直接用于竞技或有奖排行。
