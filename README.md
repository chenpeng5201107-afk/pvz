# 植物大战僵尸-函数版

一个在浏览器中运行的数学塔防游戏。用求导塔和一次性变换门，把入侵的函数化为常数。

## 从仓库拉取并运行

### 1. 准备环境

安装 [Git](https://git-scm.com/downloads) 和 [Node.js 24 LTS 或更新版本](https://nodejs.org/)，Node.js 安装时保留 npm。安装完成后重新打开终端，确认：

```sh
git --version
node --version
npm --version
```

`node --version` 应为 `v24` 或更高。项目使用 Node.js 自带的 TypeScript 运行能力与 SQLite，不需要安装 MySQL、单独的 SQLite 服务或 Codex，也不依赖特定盘符。

### 2. 克隆、安装依赖、验证并启动

在准备保存项目的目录打开终端，逐条执行以下命令；某一步报错时，先解决该错误再继续。Windows 命令提示符、PowerShell、macOS 和 Linux 终端均可使用这些命令。

```sh
git clone https://github.com/chenpeng5201107-afk/pvz.git
cd pvz
npm ci
npm test
npm run build
npm start
```

`npm ci` 按仓库中的 `package-lock.json` 安装锁定版本的依赖，首次安装需要联网。`npm test` 验证数学、战斗、账号、存档与用户管理功能；`npm run build` 先检查 TypeScript，再生成 `dist`；`npm start` 启动游戏服务，终端保持运行是正常现象。

仓库不包含 `node_modules/`、`dist/`、`data/` 和 `backups/`。从 GitHub 克隆后需要安装依赖并构建；不能直接双击 `index.html` 运行完整游戏。若仓库设为私有，克隆时需要有该仓库访问权限。

### 3. 打开游戏和用户管理

保持启动终端打开，在运行服务的同一台电脑访问：

| 页面     | 默认地址                                                             |
| -------- | -------------------------------------------------------------------- |
| 游戏     | [http://127.0.0.1:3001](http://127.0.0.1:3001)                       |
| 用户管理 | [http://127.0.0.1:3001/database](http://127.0.0.1:3001/database)     |
| 服务状态 | [http://127.0.0.1:3001/api/health](http://127.0.0.1:3001/api/health) |

游戏能打开注册页、服务状态返回 `"ok": true`，即说明服务启动成功。首次运行没有预置账号，请自行注册；新账号从第 1 关开始，通关后依次解锁十关。在启动终端按 `Ctrl+C` 可停止服务。

Windows 下，也可以在安装好 Node.js 后双击 `start-local.cmd`：缺少 `dist` 时会尝试安装依赖并构建，已有构建时直接启动。**拉取更新后仍应按下方步骤重新构建，启动脚本不会自动刷新已有的 `dist`。**

### 用户管理功能

该页面支持搜索用户、查看注册日期和有效登录数、修改用户名、重置密码、补录或修改关卡成绩、清空通关进度、强制退出所有登录和删除账号。游戏地址和管理页面地址都会打印在启动终端中。

管理操作会使该用户的旧登录失效，用户重新登录后读取最新资料和成绩。修改成绩会直接覆盖该关星数和时间；补录高关卡成绩会影响关卡解锁。清空进度和删除账号需要输入完整用户名确认，删除账号会同时移除其成绩与登录记录，操作前可运行 `npm run backup` 备份。

删除后的账号编号不会分配给新账号，旧管理页面无法用该编号误操作新用户。修改或清空成绩会更新存档版本，之前尚未同步的旧成绩不会在重新登录后覆盖管理员的调整；正常断网产生的同版本成绩仍可补传。

管理页面只在服务器监听本机地址时开放，直接访问上述网址即可，无需游戏账号登录。监听 `0.0.0.0` 或局域网地址时，管理页面和接口均不可用。管理请求还会校验来源与页面令牌；重启服务器后请刷新管理页面。页面不显示密码哈希、盐值或会话令牌。

### 数据库路径与数据归属

第一次启动会自动创建 `项目所在目录/data/game.sqlite`，账号和通关进度保存在此文件中。终端打印的是根据实际项目位置生成的绝对路径，例如 `D:\pvz\data\game.sqlite`；代码没有写死 `D:\pvz`，换目录或电脑后会自动使用新的项目位置。

源码通过 GitHub 同步，数据库不会随代码上传或拉取。新电脑首次启动会得到一个空数据库；如需保留原有账号和进度，请按下方“存档与备份”迁移。也可以用 `PVZ_DATA_DIR` 指定项目目录之外的数据目录。

### 端口被占用时

如果端口 3001 已被占用，请关闭先前的游戏服务，或用其他端口运行：

```powershell
$env:PORT = '3003'
npm start
```

上面是 PowerShell 写法；Windows 命令提示符（CMD）使用：

```bat
set PORT=3003
npm start
```

此时游戏地址为 `http://127.0.0.1:3003`，用户管理地址为 `http://127.0.0.1:3003/database`。以终端实际打印的地址为准。PowerShell 若提示禁止运行 `npm.ps1`，可改用 CMD 执行，或把命令中的 `npm` 换成 `npm.cmd`。

## 已有项目如何更新

先在原启动终端按 `Ctrl+C` 停止服务，再在项目目录执行。以下命令更新 `main` 分支：

```sh
git status
git switch main
git pull --ff-only origin main
npm ci
npm test
npm run build
npm start
```

若 `git status` 显示有本地修改，请先提交或另行保存这些修改；若切换分支或拉取失败，解决后再继续，不要用强制重置覆盖自己的代码。`git pull --ff-only` 只允许快进更新，分支存在分歧时会停止。

更新前如需留存账号和进度，可先运行 `npm run backup`。正常拉取、安装依赖和构建不会清空 `data/`，请保留该目录。启动后刷新浏览器；只拉取源码而不重新构建，`npm start` 仍会提供旧的前端页面。

## 已实现内容

- 十章有限波次关卡，依次解锁；逐步引入新函数，通关后保存最高星数和最快用时，总计 30 星。
- 5 行 × 9 列棋盘。敌人从右向左移动，碰到求导塔停下啃咬；漏怪扣基地生命。
- 求导塔基础射程为同一行前方两格；射程内有前方求导塔时，继承它的最远攻击位置，可连续传递。前塔被回收或摧毁后立即重算射程。
- 对数、指数、反正弦、正弦、平方、倒数六种一次性门。
- 单格、3×3 范围、整行三档炸弹，种下后等待敌人经过所在格中点才引爆；爆炸不受公式复杂度影响，不伤己方单位。
- 一次函数、多项式、指数、对数、三角、反三角、根式、分式、嵌套九类敌人。
- 从经过解法验证的模板随机生成系数和结构；同一对局重开保留随机种子。
- 准备阶段自由布阵；战斗可暂停布阵，暂停会冻结能量增长、移动、冷却和攻击。
- 敌人占据的空格也能补种。门在敌人经过格子中点时触发，同一时刻先结算门、再结算子弹；已过中点的敌人不补触发，门保留给下一名敌人。
- 塔可拦住尚未过中点的同格敌人，不会把敌人推回；已过中点的敌人不会被新塔追溯拦截。
- 原创程序绘制的纸上花园角色、射程提示、公式预览、手册、效果音与反馈动画。
- 注册、登录、退出、服务器存档、断线成绩重试；密码使用 scrypt 加盐哈希，登录令牌只以哈希保存在数据库中。
- 切换浏览器标签页自动暂停；支持减少动态效果的系统偏好。

| 打开手册           | 点击手册或按 `?`                                         |

| 4    | 对数的回声：对数函数、指数门             | 4–5        |
| 5    | 正弦的波纹：正弦函数、反正弦门           | 5–6        |
| 6    | 反向的旋律：反正弦函数、正弦门、范围炸弹 | 6–8        |

| 8    | 分母的另一边：分式、倒数门               | 10–12      |

| 10   | 花园的协奏：综合挑战                     | 16–20      |

第九关起的 `e^(sin x)` 需要先经过 ln 门、再经过反正弦门。可分别在第 9、第 7 列设门，炮台保持在第 4 列及后方。

| 炸弹     | 范围                             | 能量 | 冷却  | 解锁    |
| -------- | -------------------------------- | ---- | ----- | ------- |
| 单格炸弹 | 所选一格                         | 200  | 30 秒 | 第 2 关 |
| 范围炸弹 | 所选格周围 3×3，边缘裁切到棋盘内 | 350  | 45 秒 | 第 6 关 |
| 清行炸弹 | 所选行所有已登场敌人             | 500  | 60 秒 | 第 9 关 |

炸弹在战斗开始后使用，种下即扣能量并开始冷却，不可回收。炸弹与塔、门互斥占格，不能重叠放置；放置失败不扣能量、不启动冷却。没有敌人触发时，炸弹会一直留在格子里；必须有敌人经过炸弹所在格的中点才引爆，仅有敌人处于爆炸范围内不会触发。已经过中点的敌人不补触发，炸弹保留给下一名敌人。暂停时可种下，恢复后仍需等待敌人踩到。各类炸弹独立冷却；同一敌人被爆炸或子弹重复覆盖，也只结算一次消灭奖励。小屏卡牌栏可横向滚动。

## 数学规则与当前边界

本版所有关卡统一约定 **0 < x < 1**。反三角化简、对数、根号与倒数遵守这个区间上的定义域。

数学核心保存表达式树，不使用 `eval`，不把公式当作可执行字符串。支持和、积、常数次幂、链式法则、常见三角/反三角函数与指数/对数的求导。常数判定使用符号化简，不使用数值抽样。

- 支持精确的逆运算与 `sin²(u) + cos²(u) = 1` 等已实现恒等式。
- `arcsin(sin u) = u` 仅在已证明的主值区间内使用。
- 先校验定义域，再化简，避免把除零等非法运算“消掉”。
- 定义域采用保守的区间计算；无法证明合法的操作会显示提示并保持原式，已触发的门仍消耗。
- 为避免恶意或错误布阵导致表达式无限膨胀，运算结果超过 160 个节点时不执行，并提示改用其他路线。
- 这不是通用计算机代数系统。十章关卡的全部生成模板和标准解法均有自动测试覆盖。
- 大系数不会凭空增加生命值；需要的求导次数由函数结构决定。

## 开发与验证

首次克隆后先按上文执行 `npm ci`。需要修改代码并实时预览时，在项目目录启动开发模式：

```sh
npm run dev
```

默认开发前端为 `http://127.0.0.1:5173`，后端为 `http://127.0.0.1:3001`。`npm run dev` 同时启动两者，因此先停止之前的 `npm start`，避免占用同一个后端端口。开发模式下，用户管理仍直接访问 `http://127.0.0.1:3001/database`。

另开终端执行检查和测试：

```sh
npm run check
npm test
```

验证正式构建时，先按 `Ctrl+C` 停止开发服务，再执行：

```sh
npm run build
npm start
```

`npm start` 提供已经构建的网页和 API，不会自动构建或热更新前端。

构建在进程内执行 TypeScript 转译与 Terser 压缩，避免某些受限 Windows 环境禁止构建器启动子进程的问题。正式开发环境可直接使用上述 npm 命令。

自动测试包括随机函数可解性、导数数值交叉检查、定义域边界、门与子弹结算顺序、射程、暂停、啃塔、重复命中、所有关卡的合法通关路线、账号会话、数据库持久化与用户隔离。测试数据库使用单独的临时目录，不改动正式存档。

## 存档与备份

运行以下命令生成一致性的 SQLite 快照，支持服务仍在运行时执行：

```powershell
npm run backup
```

备份保存到 `backups/game-时间戳.sqlite`。不要仅在运行中复制主 `.sqlite` 文件：WAL 模式下，最新内容可能仍在同目录的 `-wal` 文件中。

跨电脑迁移或恢复已有存档：

1. 在原电脑的项目目录运行 `npm run backup`，找到终端打印的 `backups/game-时间戳.sqlite` 文件。
2. 在目标电脑克隆项目、安装依赖并构建；如果服务已经启动，先用 `Ctrl+C` 停止。
3. 如果目标电脑已有 `data` 目录，先将整个目录改名留存，再创建一个新的 `data` 目录，避免覆盖原存档或混用旧的 WAL 文件。
4. 单独传输备份文件，把它放入目标项目的新 `data` 目录，并改名为 `game.sqlite`。
5. 运行 `npm start`，使用原账号密码登录，检查关卡进度。

不要在服务运行时替换数据库。如果配置过 `PVZ_DATA_DIR`，备份和恢复应使用该变量指向的数据目录；备份输出仍在项目的 `backups/` 下。数据库备份包含账号与存档，保持在 Git 忽略范围内，不要提交到仓库。

更新源码或 `dist` 时保留 `data`。更换电脑后，要一并迁移数据库才能继续使用原账号。

从三关版更新后，请重启服务。服务会在一个数据库事务中升级旧存档的关卡限制，保留账号、会话、已有第 1–3 关的星数和最快成绩，并继续解锁第 4 关；未通关的账号按已有进度解锁。更新前可先运行 `npm run backup` 留存快照。

账号编号和存档版本的升级同样在启动时自动执行，保留现有用户编号、密码、有效会话和已保存成绩。更新后请重新构建、重启服务并刷新游戏页面。旧版浏览器中没有版本信息的未同步成绩缓存会被清除，避免覆盖管理员修改后的存档；已写入数据库的成绩不受影响。

## 当前版本范围

- 默认只监听本机 `127.0.0.1`，没有发布到公网。
- 将源码上传 GitHub 不会自动运行游戏服务。本项目需要 Node.js 后端，不能仅通过 GitHub Pages 运行完整的登录与存档功能。
- 保存的是账号和通关进度，不保存半途离开的战斗现场。
- 没有邮箱/短信找回密码、联机或排行榜。
- 通关成绩由本地客户端上报；本版不承诺竞技防作弊，不应直接用该接口做有奖排行榜。
- 手机浏览器可查看和操作界面，战斗仍优先面向电脑横屏。小屏推荐横屏使用。
- 将来公网部署需要配置 HTTPS、`COOKIE_SECURE=true`、生产环境和备份；仅把监听地址改成公网地址并不等于完成正式上线。

## 环境变量

| 名称            | 默认值          | 含义                      |
| --------------- | --------------- | ------------------------- |
| `PORT`          | `3001`          | HTTP 端口                 |
| `HOST`          | `127.0.0.1`     | 监听地址                  |

```powershell
$env:PVZ_DATA_DIR = 'E:\pvz-data'
```
